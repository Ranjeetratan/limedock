### Your Claude skills folder is a junk drawer. We built a catalog instead.

*LimeDock Directories is a searchable Claude skills directory — plus Agents and Systems — for people who are drowning in bookmarks and still shipping GTM by hand.*

---

I have a Chrome folder called “Claude skills.”

It has 47 links. Three of them still work. Two contradict each other. One is a screenshot of a screenshot of a Twitter thread. And somehow I still open a blank Claude chat and type “write a blog post” like it’s 2023.

If that sounds familiar, you’re not bad at AI. You’re just collecting ingredients without a kitchen.

Everyone’s drowning in the same pile right now: random skill lists, “top 50 Claude skills” roundups, Agent repos with zero install instructions, and that one Notion page your teammate swore they’d organize “this weekend.” The problem isn’t scarcity. It’s that **inspiration doesn’t come with a filter**, and a skill you can’t find in 20 seconds might as well not exist.

So we built [LimeDock Directories](https://www.limedock.com/directories) — a Claude skills directory with Agents and Systems, filterable by type, category, and industry. Steal ideas freely. Then, if you want the workflows live in your stack, talk to us.

### The actual problem (not the LinkedIn version)

Claude skills are genuinely useful. So are agents. So are the “install this pack” repos circulating right now.

What’s broken is the **operating system around them**:

1. **Discovery is chaos.** Half the good stuff lives in someone’s GitHub. The other half lives in a reply to a reply.
2. **Everything is flat.** A one-shot “rewrite this email” skill and a multi-step outbound system get treated like the same object.
3. **Nobody tells you the order.** You install seven skills, run them in the wrong sequence, and decide “AI content doesn’t work.”
4. **Bookmarking feels like progress.** It isn’t. Your pipeline still starts with a human copy-pasting into Slack.

We kept hitting this while building LimeDock. So instead of another “ultimate list,” we shipped a catalog we’d actually use.

### What we built: LimeDock Directories

[Directories](https://www.limedock.com/directories) is simple on purpose:

- **Skills** — reusable playbooks Claude loads for a specific job (copy, SEO, CRO, research, etc.)
- **Agents** — multi-step workers that plan, review, or orchestrate across tools
- **Systems** — skill architectures: the stack and sequence for a whole workflow

You can filter by type, category (Sales, Marketing, Growth, Design, Ops, Engineering, Product…), and industry (SaaS, agency, ecommerce, and so on). There’s search. There are detail pages with install notes, how-to, example prompts, and related skills.

![Directories search, industry and category filters, and conversion strip about owned automation](/Users/rupesh/Limedock/content/medium-directories/04-conversion-strip.png)

*Search + industry + category — and a clear path if you want help shipping*

Right now the catalog sits at **194 skills, 10 agents, and 12 systems** (216 entries). That number will move. The point isn’t “biggest list.” The point is **you can find the thing and understand how it fits next to other things**.

### How to use it (without becoming a skills hoarder)

#### Skills vs Agents vs Systems

Think in layers:

| Type | What it is | When to open it |
|------|------------|-----------------|
| **Skill** | A focused playbook | “I need a better SEO pass / cold email / anti-slop edit” |
| **Agent** | A multi-step worker | “I need something that reviews, orchestrates, or runs a loop” |
| **System** | An architecture of skills | “I need the whole content / outbound / experiment machine” |

Most people start by starring skills. Better move: **start from a System**, then install the minimum skills in order.

![Grid of LimeDock Systems cards including Blogging Content Engine and Brand Creative System](/Users/rupesh/Limedock/content/medium-directories/02-systems-tab.png)

*Systems = composable skill architectures, not vibes*

### The twist nobody puts in the roundup posts

A catalog will not ship your workflows.

I mean that literally. Installing a skill does not:

- update the CRM when a demo books  
- post the draft into the right Slack channel with the right reviewer  
- keep your experiment backlog from rotting  
- make sales and marketing stop reinventing the same sequence every Monday  

Skills show **what’s possible**. Agents show **how work can be orchestrated**. Systems show **how pieces fit**.

None of that is the same as **owned automation** — durable workflows that live in *your* Slack, CRM, and internal tools, with code you own.

That’s the gap LimeDock exists for.
